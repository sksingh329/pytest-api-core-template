# Repository Profile

_Generated by test-planner. Cached summary reused across plans — regenerate if conventions change._

- Project type: pytest-based API automation suite for gorest.in, built on the `pytest_api_core` pytest plugin (installed in `.venv`), configured via `pytest.ini` (`api_env=dev`, `api_settings_module=config.settings`, `api_dotenv_file=.env`).
- HTTP library: `pytest_api_core.client.api_client.APIClient` (wraps the plugin's HTTP client); exposed to tests via the `api_client` fixture in `tests/conftest.py`.
- Authentication mechanism: Bearer token via `pytest_api_core.auth.auth_handlers.BearerAuth`. `tests/conftest.py` overrides the plugin's default `api_client` fixture (session-scoped) to inject `BearerAuth(token)` where `token = get_env("BEARER_TOKEN", required=True)`. A parallel `blocked_api_client` fixture (session-scoped) uses `BEARER_BLOCKED_TOKEN` for negative/403 tests.
- Fixture strategy: Plugin auto-registers `api_config` and a base `api_client`; `tests/conftest.py` overrides/extends with `api_client`, `blocked_api_client`, `base_url`, `new_user_payload` (Faker-based creation payload), and `created_user` (creates via POST `/public/v2/users`, yields the `APIResponse`, deletes in teardown). `faker_seed` fixture randomizes Faker's seed per test.
- Assertion strategy: Fluent chain via `assert_that(response)` from `pytest_api_core.assertions`, e.g. `.status_is(code)`, `.has_key(k)`, `.key_equals(k, v)`, `.json_path("$.x").equals(v)`.
- Schema validation strategy: `assert_that(response).matches_schema(schema_dict)` (in `pytest_api_core/assertions/response_assertions.py`), backed by the `jsonschema` library (installed in `.venv`). Schema dicts live in `models/<resource>.py` (e.g. `models/users.py` defines `user_schema` and `users_list_schema`) — not yet referenced by any existing test, but established as the convention location for JSON-schema dicts.
- Test organization: Tests live under `tests/<resource>/test_<resource>.py` (e.g. `tests/users/test_users.py`), grouped in a `Test<Resource>` class marked with a resource-specific pytest marker (`@pytest.mark.user`, registered in `pytest.ini` under `markers`). Endpoint path constants are declared module-level (e.g. `USERS_PATH = "/public/v2/users"`).
